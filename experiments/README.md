# Performance experiments

Experiments are evidence, not production architecture. The fixed mathlib workload is generated by
`select-mathlib-workload.sh`; the committed 62-file manifest is its deterministic `sample` output.
`profile-run.sh` wraps a command with explicit project-build and formatter-cache states, monitors the
whole process group, and retains metadata, standard streams, phase records, and an output digest.

For example:

```sh
experiments/select-mathlib-workload.sh ~/Code/mathlib4 sample > /tmp/mathlib-sample.txt
experiments/profile-run.sh \
  --name exact-import-sample \
  --project-root ~/Code/mathlib4 \
  --build-state ordinary-built \
  --cache-state formatter-cache-cold \
  --sources experiments/workloads/mathlib-v4.32.0-sample.txt \
  -- experiments/run-pure-lean-workload.sh import ~/Code/mathlib4 \
     experiments/workloads/mathlib-v4.32.0-sample.txt
```

The wrapper always sets `LEAN_NUM_THREADS=1`. Its default hard stops are 8 GiB aggregate RSS and
256 MiB new swap. A command may print `phase.<name>_ms=<integer>` and `cache.<name>=<integer>` lines to make its
internal phase times and cache accounting separately inspectable; the full command output remains
authoritative. `lean-fmt` emits both under `LEAN_FMT_PROFILE_PHASES=1`, which the wrapper does not
set for you — a profile of the phase schema has to ask for it.

`docs/projects/ruff-19-performance/notes/01-phase-schema.md` is the schema those names belong to, and
`evidence/01-workloads.md` in the same stack is the frozen workload set this repository measures
against.
