# Every command syntax kind the frozen corpus contains that no layout emits, and who owns it.
#
# `RLF-FINAL`'s stop rule is "zero silently unowned accepted syntax kinds in the frozen corpus". The
# refusals were never unsafe -- an unclaimed command is emitted as its own bytes, which is the
# conservative path `RLF-COMMANDS` built and `tests/printer/run.sh` pins. They were *silent*:
# `run-printer-sample.sh` counted them into `evidence/01-printer-sample.txt` and nothing compared that
# count against anything, so a kind arriving in the corpus produced one more line in a report nobody
# was required to read. This file is the thing to read, and the script now fails on a kind that is not
# in it.
#
# **This is not the clearance table `notes/04-extensions.md` §5 refused**, and the difference is the
# direction. That table would have *widened* what the printer collapses: each entry a claim about
# `Lean/Parser/Term.lean` that, when it went stale, emitted Lean that does not parse. This one widens
# nothing. Every kind here is refused whether or not it is listed, no entry changes an output byte,
# and a stale entry cannot break a parse -- it can only mis-describe one. Its failure mode is a wrong
# sentence, not wrong Lean, and the gate below is what makes even that loud.
#
# **Kinds, not counts.** The gate compares the set of kinds, because a count moves whenever the sample
# moves and a disposition does not. `evidence/01-printer-sample.txt` is where the counts live.
#
# The counts do say one thing worth writing down, though, because it is a check on this file rather
# than on the printer: the three dispositions **partition** the sample's refusals exactly.
#
#     guard 196  +  core 542  +  corpus 417  =  1155  =  commands 2734 - canonical 1579
#
# No kind is counted twice and none is missing, and that is arithmetic rather than assertion. Any
# future edit that leaves a kind out shows up as a sum that no longer closes.
#
# **How to read a kind string.** A kind beginning `Lean.Parser.` is declared by the compiler this
# stack pins at v4.32.0 and its grammar is quotable. Anything else was declared by the corpus being
# formatted -- by a `syntax` command in mathlib or Batteries -- and this printer cannot read its
# declaration at all. That distinction is visible in the kind string and nowhere else in the tree,
# which `Tree.nodeKinds`' docstring states and this file depends on.
#
# The three dispositions:
#
#   guard    A layout claims this kind and a runtime guard refused these instances. The reason is
#            cited in `LeanFmt/Printer.lean` at the guard itself. These are the interesting ones: the
#            printer knows the grammar and declined anyway.
#   core     A command kind the pinned compiler declares and no layout in this stack claims. This is
#            scope, not soundness -- `RLF-COMMANDS` claimed the kinds it could cite a grammar for and
#            stopped. Each keeps its bytes.
#   corpus   A kind declared by the corpus being formatted, not by the compiler. `RLF-EXTENSIONS`
#            owns these as a class rather than one at a time, and that is the whole point of it: the
#            set is open -- mathlib can add a command tomorrow -- so an answer per kind is one this
#            stack cannot finish writing. The `.keep`/verbatim default is sound for every member,
#            including the ones that do not exist yet.
#
# ---------------------------------------------------------------------------------------------------
# guard -- a layout claims the kind; these instances were refused, with the citation
# ---------------------------------------------------------------------------------------------------
#
# `section`: every refusal is an attribute bracket, and the sample's count is exactly accounted for --
# 35 `@[expose] public section` plus 1 `@[expose] public noncomputable section` = the 36 in the
# census, and zero refused for any other reason. `spaceSeparated` puts one space between every pair of
# tokens, so a run holding `@[` and `]` emits `@[ expose ]`. Guard and citation:
# `Printer.lean`, `Tree.opensAttributeBracket` and `canonical?`'s `section` arm.
guard    Lean.Parser.Command.section
#
# `open`: all 4 are `openOnly` (`open Function (comp)`), zero are `openRenaming`. `canonical?` claims
# `openSimple`, `openScoped` and `openHiding` -- the three alternatives that are flat runs of
# identifiers -- and refuses the two that are not, because a flat run emits `Foo ( a b )` for the
# brackets and `a → b , c → d` for the separator. Citation: `canonical?`'s `open` arm,
# `Lean/Parser/Command.lean:724-739`.
guard    Lean.Parser.Command.open
#
# `instance`: excluded by `declarationShell?` and its grammar says why
# (`Lean/Parser/Command.lean:202-204`). Its `declId` is *optional* -- anonymous instances are ordinary
# Lean -- so a name-terminated shell would have to end at the keyword instead, and `optNamedPrio` is
# bracketed, so one space between its tokens gives `( priority := 5 )`. Neither is hard; both are
# separate claims needing separate fixtures.
guard    Lean.Parser.Command.declaration/Lean.Parser.Command.instance
#
# `example`: structural, and the cleanest refusal here. `def «example» := leading_parser "example" >>
# ppIndent optDeclSig >> declVal` (`Lean/Parser/Command.lean:208-209`) has **no `declId` at all** -- an
# example has no name. The shell layout is name-terminated by construction, so there is nothing for it
# to claim, and `shapeDeclId?` returning none is that fact rather than a limitation.
guard    Lean.Parser.Command.declaration/Lean.Parser.Command.example
#
# ---------------------------------------------------------------------------------------------------
# core -- the pinned compiler declares it; no layout in this stack claims it
# ---------------------------------------------------------------------------------------------------
#
# These are the kinds `RLF-COMMANDS` could have claimed and did not, and the honest one-line reason for
# every one of them is the same: a layout costs a grammar reading and a fixture, the conservative path
# already emits them correctly, and no prompt in this stack was scoped to buy the rest. `variable` and
# `in` are the two worth naming as future work -- 385 of the 542 core refusals between them -- and
# `moduleDoc` is the one that should probably never be claimed, since its body is prose.
core     Lean.Parser.Command.variable
core     Lean.Parser.Command.in
core     Lean.Parser.Command.moduleDoc
core     Lean.Parser.Command.attribute
core     Lean.Parser.Command.notation
core     Lean.Parser.Command.include
core     Lean.Parser.Command.assertNotExists
core     Lean.Parser.Command.macro
core     Lean.Parser.Command.syntax
core     Lean.Parser.Command.macro_rules
core     Lean.Parser.Command.export
core     Lean.Parser.Command.mixfix
core     Lean.Parser.Command.elab
core     Lean.Parser.Command.deprecated_module
#
# ---------------------------------------------------------------------------------------------------
# corpus -- declared by the code being formatted; unreadable by construction
# ---------------------------------------------------------------------------------------------------
#
# `lemma` is the one to understand, because it is the largest single bucket in the census (393) and it
# looks like a core declaration and is not. `Mathlib/Tactic/Lemma.lean:21`:
#
#     syntax (name := lemma) (priority := default + 1) declModifiers
#       group("lemma " declId ppIndent(declSig) declVal) : command
#
# and a macro then rewrites the node to `Lean.Parser.Command.declaration`. So its *shape* deliberately
# mirrors the one `declarationShell?` reads, and the shell layout would very likely be correct on it --
# but "very likely" is the word this stack does not accept. The kind is declared by the corpus, the
# corpus can change it, and no gate here would notice. It keeps its bytes.
corpus   lemma
corpus   Batteries.Tactic.Alias.alias
corpus   Batteries.Tactic.Alias.aliasLR
corpus   Mathlib.Tactic.scopedNS
corpus   commandSuppress_compilation
corpus   adaptationNoteCmd
