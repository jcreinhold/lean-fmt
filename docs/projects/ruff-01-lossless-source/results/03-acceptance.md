# RLS-FINAL — acceptance

The projection is exercised by an oracle that shares no code with it, over this repository's own 18
modules and the frozen 62-module mathlib sample. Every successful case reconstructs byte-for-byte.

The oracle found two defects on its first real inputs, both of which made ordinary files fail
outright. `RLS-IMPL`'s fixtures could not have caught either: both are properties of real code that
no fixture under 1 KB exhibits.

The size profile the stack recorded as its largest open risk now exists. The headline is that the
artifact is **10.26x the source on real mathlib** against 3.93x on the fixture — and that both
numbers come from one cost model, because ratio-against-source was never the schema's property.

## The corpus is an oracle, not a restatement

`tests/lossless/check_projection.py` shares no module with the product. It re-derives every claim
from the artifact JSON and the source file alone: it digests the normalized bytes itself, walks the
token stream, recovers each trivia run's start by contiguity, slices the source at every recorded
boundary, checks each run contains the form its kind names, and rebuilds header + tokens + tail. It
can therefore contradict `structurallyValid` rather than agree with it by construction — which is
exactly what it did, twice.

Its corpus is this repository's own Lean modules rather than a fixture set: they are real,
non-trivial, always present, and they change as the project changes. Production `LeanFmt/*` modules
cannot carry the plugin without depending on themselves, so the exact frontend is the only path for
them; `tests/check/run.sh` remains what proves the two producers agree.

| corpus | modules | source | tokens |
| --- | --- | --- | --- |
| this repository | 18 | 132 KB | 20,239 |
| frozen mathlib sample | 62 | 689 KB | 119,856 |
| generated byte-exotic | 8 | — | — |

The generated cases are CRLF, `#exit`, `#exit` in CRLF, no final newline, header-only, comments
after the last command, Unicode, and an ambiguous parse. They are generated rather than committed
because git normalizes line endings: a CRLF fixture cannot survive as a file in the tree.

Thirteen mutations — wrong digest, wrong length, four boundary lies, a dropped token, a shifted
token, a trivia hole, a misclassified run, a fabricated position, two dangling references, a stale
schema — are each rejected. A validator that accepts a lie proves nothing about what it accepted.

## Two defects, both of which broke ordinary files

### `#exit` made every containing file fail

`terminalStop` recorded where the terminal command *ends*. Neither producer puts a terminal into
`commands`, so the `#exit` text itself was covered by no token, and the stream stopped short of the
boundary the projection claimed. `structurallyValid` rejected it — correctly, given what was
recorded — so the artifact was never usable:

```
$ lean-fmt check --root . --json --no-cache tests/check/ExitTail.lean     # before
{"status":"infrastructure-failure",
 "diagnostics":["invalid exact analysis for tests/check/ExitTail.lean"]}    exit=2
$ lean-fmt check --root . --json --no-cache tests/check/ExitTail.lean     # after
{"status":"clean","findings":[]}                                            exit=0
```

`terminalStop` is now where the terminal *begins*, which is where the modeled token stream ends. The
tail `[terminalStop, normalizedBytes)` reconstructs verbatim and covers `#exit` plus the remainder
Lean never parses. For `eoi` it is end of file, unchanged, because trailing trivia is greedy up to
the next token's text — measured: a file ending in `\n\n-- comment\n` records that comment inside
the last command's trailing trivia, not stranded before `eoi`.

### `choice` nodes ran the token stream backwards

`{ findings, normalized, lineEndings, patch }` in this repository's own `Application.lean` parses
both as a structure instance and as a set-like literal. The parser emits a `choice` node holding
both trees over one byte range, so walking every alternative spelled those bytes once per
alternative:

```
FAIL token 2311 leading: trivia stops at 17266, not 17220
```

Only the first alternative contributes tokens now. `Lean/Parser/Basic.lean:1418-1440` is what
licenses picking any one of them: `longestMatchStep` restores each alternative to the same
`startPos` and keeps it only when its score ties, and that score's first component is the stop
position. Equal start, equal stop, one tokenizer — the alternatives differ in tree shape alone. The
`choice` node itself stays in `nodes`, so the ambiguity is visible rather than silently resolved.

Incidence is not marginal: 1 of this repository's 18 modules, and 1 of 5 sampled mathlib modules
(`Mathlib/Tactic/Conv.lean`, 2 nodes). Every such module was rejected whole.

62 modules, all successful, no failures, byte-identical reconstruction on every one.

| new swap | 256 MiB | **-8 MiB** (freed) |
| pressure level | 1 | **1**, not exceeded |

Wall clock 239.4 s for 62 modules. Analysis is the whole cost: 162.9 s total, median 1.96 s, max

### The artifact is O(tokens + nodes), and the sample proves it

| model | fit | R² |
| --- | --- | --- |
| `artifact ≈ 24.86 × (tokens + nodes)` | per element | **0.9986** |
| `artifact ≈ 10.59 × source_bytes` | per source byte | 0.9436 |

Which divisor is stable is the whole answer. Across the 62 modules, bytes-per-element varies 2.8x
(median 23.91) while bytes-per-source-byte varies 7.0x (median 9.36, max 16.41). The driver is
token density, which itself varies 16.1x: mathlib spends 6.28 source bytes per token, the
`LocalSyntax` fixture 23.0. That single number is the entire distance between 3.93x and 10.26x —
the fixture is comment-heavy, mathlib is dense. Same schema, same cost, different files.

| measure | sample |
| --- | --- |
| source | 688,850 B |
| artifact | 7,067,206 B |
| ratio, aggregate / median / max | 10.26x / 9.36x / 16.41x |
| bytes per element, median / max | 23.91 / 62.10 |
| largest artifact | 660,805 B (`Analysis/Normed/Module/Multilinear/Basic.lean`, 63,690 B source) |

The two modules above 40 B/element are 129 B and 295 B files where the fixed schema strings and two
digests dominate — the same effect already recorded for a 34-byte module at 29x. The shipped bound
`< 1024 + 40 * (tokens + nodes)` holds on **62/62**, tightest margin 0.637; its additive term is
what absorbs those two.

10.26x is a real cost, not a comfortable one, and the roadmap asks for "compact". Two measured
facts bound the argument. The rejected derived field-name encoding was 3.11x larger than the shipped
arrays, so it would have measured ~32x and ~22 MB on this sample. And the artifact lands in the
`.olean`: measured `olean_delta_bytes` 133,424 against `artifact_bytes` 132,758, so the payload
costs its own size in the build directory and nothing more.

### The node table is 45.6% of a real artifact and nothing reads it

Decomposing `Mathlib/Data/Stream/Init.lean` (411,671 B artifact, 25,092 B source):

| table | bytes | share | per element |
| --- | --- | --- | --- |
| tokens | 218,673 | 53.1% | 32.0 B × 6,834 |
| nodes | 187,902 | **45.6%** | 18.3 B × 10,249 |
| kinds | 4,750 | 1.2% | 165 interned |
| fixed + findings | 346 | 0.1% | — |

`RLS-IMPL` recorded that no consumer reads `nodes` and that its granularity was unmeasured. It is
now measured: dropping it would nearly halve the artifact, taking the sample from 10.26x to roughly
5.6x. The roadmap requires syntax boundaries, so it ships, and the probe differential below is the
only thing that currently reads it at all. Whether the full flattened tree is the right granularity
is the largest open question this stack hands forward — but it is now a question with a price on it.

## Differential: three independent producers agree

- `tests/check/run.sh` asserts the exact frontend's artifact equals the compiler plugin's,
  byte-for-byte, on the full JSON. They reach `ModuleArtifact.ofParsedModule` with the same
  arguments, so this is structural rather than a coincidence that could drift.
- `check_projection.py` re-derives the projection from source, sharing no code with either.
- `experiments/pure-lean-core`'s probe plugin shares no module with `LeanFmt` and records each
  command's `getRange?` independently. Its command list matches the projection's root nodes — the
  nodes with no parent, each widened to the hull of the leaves beneath it, which is what
  `getRange?` returns.

That last check was **source-false**: it still asserted on `artifact["commands"]` and
`artifact["sourceBytes"]`, which `RLS-IMPL` removed, so it could not run at all. It is repaired to
compare against root nodes and verified on two mathlib modules
(`experiments/results/module-artifact-sample-20260716T124008Z`). It is not re-run in full: it
rebuilds each module twice plus an oracle pass, and it measures compile-time plugin overhead, which
is a prior stack's claim and not `RLS-FINAL`'s.

## Redundant DTOs removed

- `LosslessSource.tail` — a `SourceRange` accessor with no callers. The tail is
  `[terminalStop, normalizedBytes)`; the field doc now says so, which is what the accessor was for.
- `Patch.sourceDigest` — a redundant accessor. `Patch.matchesSource` is the interface; handing a
  caller the digest invites it to do the comparison itself, which is the weaker check.

## Remaining uncertainty

- **The node table.** 45.6% of a real artifact, read by nothing but the probe differential.
  Measured, priced, and unresolved.
- **`structurallyValid` rejects any non-`.original` token.** Every accepted case across 80 real
  modules and 8 exotic ones parses to `original` leaves throughout, consistent with
  `01-source-authority.md`'s `synthetic=0 missing=0`. That is now measured far more broadly than on
  fixtures, but it is still not proven for all accepted source. A module with a synthetic leaf in a
  parsed command would be an ordinary miss — correct, but silently slower.
- **The sample is 62 modules, not mathlib.** Aggregate ratio on the full library is an
  extrapolation, and the sample's 16.1x spread in token density is exactly why extrapolating a
  ratio is unsound. The per-element model is what carries across; the ratio is not.
- **`choice` alternatives beyond the first are dropped from `nodes`.** The compiler source proves
  they spell identical text, so reconstruction is unaffected. A consumer wanting to know *which*
  parses were possible cannot; it sees only that the range was ambiguous.
- **Trivia classification is the producer's.** The scanner mirrors `whitespace`'s grammar over
  spans Lean already delimited. The oracle checks each run contains the form its kind names, which
  is a weaker statement than "Lean would classify it identically".
