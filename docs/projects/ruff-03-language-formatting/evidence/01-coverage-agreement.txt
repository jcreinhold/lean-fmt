# Do the two coverage measurements agree, and why?
#
# `state/current.md` claimed they "agree exactly, and keep agreeing as it grows": the Python probe's
# `claimable + namespace + end + open` equalled the printer's `canonical=` at 859. When a new
# production module (`LeanFmt/LanguageServer.lean`, `ruff-17` `RLP-DOCUMENTS`) grew the corpus, the
# aggregates parted: probe 934, printer 935. This file is the per-module comparison that says why.
#
# Method. `experiments/run-projection-shape.sh` selects its corpus with `git ls-files`; copy it into
# `experiments/` (the script derives the repo root from its own path, so it must run from there) with
# the module list replaced by one file, and run it once per module:
#
#   sed 's|^modules=$(git ls-files.*|modules="$LFMOD"|' experiments/run-projection-shape.sh \
#     > experiments/.probe-one.sh
#   for m in $(git ls-files 'LeanFmt/*.lean' 'LeanFmt.lean' 'Main.lean'); do
#     LFMOD=$m bash experiments/.probe-one.sh /tmp/one.txt
#   done
#
# and read `canonical=` per module out of `tests/printer/run.sh`'s corpus section.

printer_total=929   probe_total=928   modules_compared=28

# modules where the two disagree (printer canonical, probe claimable+namespace+end+open)
LeanFmt/Cache/Decision.lean   printer=11  probe=10
LeanFmt/Cache/Spec.lean       printer=31  probe=30
LeanFmt/Imports.lean          printer=20  probe=21

# Every other module agrees, including LeanFmt/LanguageServer.lean, which has been re-checked at each
# of its sizes: 67, then 71 (`ruff-17` RLP-FINAL). Its declaration count moves with the module and
# every one of them is structurally claimable, so it contributes equally to both totals.
#
# Re-run at `ruff-19` RPR-IMPL, which added `LeanFmt/Profile.lean` and edited three modules: 914/913
# over 27 modules became 921/920 over 28. The same three modules disagree, by the same amounts, and
# the gap is still exactly +1 -- the new module is structurally claimable throughout and moves both
# totals together, which is what this file exists to be able to say.
#
# Re-run again later in RPR-IMPL, which added declarations to `LeanFmt/Cache.lean` and
# `LeanFmt/Project.lean` while removing the whole-workspace fallback digest from a cold run: 921/920
# became 925/924 over the same 28 modules. Both edited modules were re-probed individually rather
# than assumed -- Cache.lean 49/49, Project.lean 35/35 -- so neither joined the disagreement list and
# the gap is still +1 for the two reasons below.
#
# And again for the batched setup probe in the same prompt, which added declarations to
# `LeanFmt/Application.lean` and `LeanFmt/Project.lean`: 925/924 became 927/926. Both were re-probed
# individually -- Application.lean 112/112, Project.lean 36/36 -- and again neither disagrees.
#
# And again at `ruff-12b` RGR-FINAL, which added `metaCodes` and `metaDescription?` to
# `LeanFmt/Rules.lean` and one `explain` branch to `LeanFmt/Cli.lean`: 927/926 became 929/928 over the
# same 28 modules. Both edited modules were re-probed individually rather than assumed --
# Rules.lean 90/90 (88 claimable + 1 namespace + 1 end), Cli.lean 80/80 (76 + 1 + 1 + 2 open) -- so
# neither joins the disagreement list and the gap is still exactly +1 for the two reasons below.
#
# `tests/printer/run.sh` is what caught this, which is the point of it: the edit was two declarations
# in a rule catalog and had nothing to do with the printer, and the prompt making it had no reason to
# think about this corpus. That is precisely the failure mode `RLF-FINAL` built the chain for.

# Two causes, in opposite directions.
#
# 1. The probe's canonical formula omits `Lean.Parser.Command.section`, and the printer lays sections
#    out. This corpus has exactly 2, one in each `Cache/` module (Decision.lean:97, Spec.lean:85).
#    `state/current.md` said "this corpus contains none of either [`section` or `universe`]"; that was
#    already false when written -- the probe's own command census has listed `2 Lean.Parser.Command.section`
#    throughout.
#
# 2. The printer refuses one command in Imports.lean that the probe counts as structurally claimable.
#    That direction is the expected one and the probe documents it: the probe models structure only,
#    the printer also applies runtime guards (clean trivia, newline-free flat run, column 0).
#
# So the aggregate is +2 -1 = +1. The old exact agreement at 859 was +2 -2: two offsetting errors
# summing to zero, not two measurements confirming each other. A total-only comparison could not see
# that, and did not. The per-module comparison is the check that can.
