=== SECOND BREAK: a custom colEq, which the shipped guard does NOT catch ===

Found while testing prompt 04's four named cases, after 882a076 landed.

`respectsLines` refuses a gap when a cross-line node starts at-or-right of it. A custom
`withPosition(term colEq term)` creates NO node of its own: the only node here is `termTbl_____`,
and it opens at `tbl` -- LEFT of the collapsed gap -- so the census never sees it. Built-in
`tacticSeq1Indented` is caught only because it happens to be its own node, opening at the first
tactic. That was luck, not a rule.

The completion is a second clause, and it is not kind-aware: refuse a gap that lies INSIDE any
node spanning lines, as well as one with a cross-line node starting to its right. Together they
are complete. If a check compares P (right of the gap, same line) against Q (another line), the
minimal node N containing both spans lines, and either N starts at-or-right of the gap -- clause
2 -- or N starts left of it and therefore contains it -- clause 1. Same-line pairs cannot flip:
a collapse never reorders and never closes a gap below one space.

Clause 1 means the term layer fires only inside single-line commands, since a multi-line
command's own `declaration` node contains every gap in it. On the frozen sample that costs
nothing measurable -- app_slack, binder_slack and match_slack are all 0.
