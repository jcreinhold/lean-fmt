# RFP-SPEC section 6. Canonical text still violates FMT001 and FMT002: the printer does not
# subsume the lint rules, and canonicalizing shifts the offsets they index.
#
# Reproduce:
#   lake setup-file tests/check/Clean.lean > setup.json      # borrowed setup, as tests/printer/run.sh does
#   lake env lean-fmt __analyze-exact setup.json probe.lean probe.lean 8589934592 > probe.json
#   lean-fmt-tests printer-format probe.json probe.lean 100

$ cat -v -e probe.lean   # trailing whitespace on the def, and no final newline
module$
$
namespace     Alpha$
$
def v : Nat := 1  $
$
end Alpha[no final newline]

$ lean-fmt-tests printer-format probe.json probe.lean 100
module$
$
namespace Alpha$
$
def v : Nat := 1  $
$
end Alpha[no final newline]

# The printer canonicalized `namespace     Alpha` -> `namespace Alpha` (4 bytes deleted) and:
#   * LEFT the trailing `  ` on the def line   -> FMT001 still fires
#   * did NOT add a final newline               -> FMT002 still fires
# Both are correct: `  ` is the trailing trivia run of that command's last token, and a
# command extent keeps its own trailing run verbatim (Printer.lean:208-222). Whitespace at
# end-of-line is not a layout decision.
#
# The consequence for RFP-IMPL: every finding offset after column 9 of line 3 is now wrong by
# 4 bytes. Findings index the normalized source (Application.lean:420-422), so a cached FMT001
# fix applied to this canonical text lands in the wrong place. Format first, then RE-DERIVE.
