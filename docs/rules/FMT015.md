# FMT015 — report a bound variable that resembles a nullary constructor

- **Lifecycle:** preview
- **Category:** `naming`
- **Tier:** `semantic`
- **Fix:** report-only
- **Default:** off

A bound variable's name matches a nullary constructor in scope, surfaced from the compiler's
`linter.constructorNameAsVariable` diagnostic — a pattern that reads as a constructor but binds a fresh variable.
Report-only.

## Path out of preview

Graduates when it produces at least 10 audited true positives on a corpus that exercises it AND its opinionation rate is
measured under RGR-SPEC §2.4 — not just its false-positive rate. Of the ten preview rules this is the most likely to be
true-but-unwanted: naming a binder after a nullary constructor can be deliberate and readable, so a clean false-positive
count would not by itself show the rule is worth imposing.

## Example

Bad:

```lean
inductive Light where
  | red
  | green

def f (red : Light) : Light := red
```

## Using this rule

- Select: `--select FMT015` or `--select naming`
- Suppress: `-- lean-fmt: ignore[FMT015]`
