# FMT014 — report use of a deprecated declaration

- **Lifecycle:** preview
- **Category:** `deprecation`
- **Tier:** `semantic`
- **Fix:** fixable
- **Default:** off

A reference resolves to a declaration marked `@[deprecated]`; the report surfaces the compiler's own `Lean.Linter.deprecatedAttr` diagnostic unchanged. When the deprecation names a replacement and the run applies fixes, an **unsafe** rename fix is offered (a textual name swap is plausibly intended but unproven, so it applies only under `--unsafe-fixes` and is backstopped by output re-elaboration).

## Example

Bad:

```lean
def new : Nat := 0
@[deprecated new (since := "1.0")] def old : Nat := 0
def use : Nat := old
```

Good:

```lean
def new : Nat := 0
@[deprecated new (since := "1.0")] def old : Nat := 0
def use : Nat := new
```

## Using this rule

- Select: `--select FMT014` or `--select deprecation`
- Suppress: `-- lean-fmt: ignore[FMT014]`
