# FMT012 — report use of a deprecated declaration

- **Lifecycle:** preview
- **Category:** `deprecation`
- **Tier:** `semantic`
- **Fix:** fixable
- **Default:** off

A reference resolves to a declaration marked `@[deprecated]`; the report surfaces the compiler's own
`Lean.Linter.deprecatedAttr` diagnostic unchanged. When the deprecation names a replacement and the run applies fixes,
an **unsafe** rename fix is offered (a textual name swap is plausibly intended but unproven, so it applies only under
`--unsafe-fixes` and is backstopped by output re-elaboration).

## Path out of preview

Graduates report-only when it produces at least 10 audited true positives with zero false positives on a corpus that
actually uses deprecated declarations; it found none across 85 mathlib modules. The rename fix stays `unsafe` and opt-in
regardless of that outcome, because a textual name swap is plausibly intended but unproven — so graduation would enable
the report, never the fix.

## Example

Bad:

```lean
def new : Nat := 0
@[deprecated new (since := "1.0")] def old : Nat := 0
def use : Nat := old
```

Good:

```lean
def new : Nat := 0
@[deprecated new (since := "1.0")] def old : Nat := 0
def use : Nat := new
```

## Using this rule

- Select: `--select FMT012` or `--select deprecation`
- Suppress: `-- lean-fmt: ignore[FMT012]`
